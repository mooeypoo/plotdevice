# ADR 0008: IDs

Status: **Accepted** (owner, 2026-10-25, with the Milestone 2 plan)

## In short

The app gives a project and each chapter a short random ID, such as `ch-k3f9q2`. It's written once, never changes, and is only used to recognise a file again after someone renamed it outside the app. Readers of the files can ignore it.

## Decision

- **Format:** a type prefix plus six random lowercase letters and digits: `prj-7d2k9q`, `ch-k3f9q2`. That gives about 2 billion values per type, ample for one project, and it stays short enough not to clutter frontmatter.
- **Where IDs appear:**
  - `id` in `project.md`, which keys the per-user state kept in app data (ADR 0005, ADR 0006)
  - `id` in each chapter's frontmatter (ADR 0006)
  - nowhere else for now; outline cards have no IDs (ADR 0003)
- **Created by** the `IdGenerator` port, so the domain stays pure and tests can use predictable IDs.
- **Checked when a project opens.** A duplicate chapter ID, for example from a copied file, is reported and never "fixed" silently, because which copy is the original is the author's call.
- **Optional:** files without an ID work normally; they just can't be matched after an outside rename.

## Rejected

| Option | Why not |
|---|---|
| UUIDs (`3f2b8c1e-…`) | Long and noisy in a file people read |
| Sequential numbers (`ch-12`) | Collide when two copies of a project are merged |
| IDs derived from titles | Change when the title changes, which defeats the purpose |
